1. Birim Test (Unit Testing) Felsefesi

Birim Test Nedir? Bir uygulamanın en küçük mantıksal yapı taşını (genellikle tek bir metot veya sınıf) dış dünyadan (veritabanı, internet, dosya sistemi vb.) tamamen izole ederek hafızada milisaniyeler içinde test etme sanatıdır.

🚗 Otomobil Fabrikası Analojisi

Bir otomobil üretilirken fren balatası önce laboratuvarda tek başına test edilir (Unit Test). Araba tamamen birleştirilip piste çıkarılmaz (E2E Test). Eğer fren balatası laboratuvarda bozuk çıkarsa, arabayı piste çıkarıp benzin ve zaman yakmanın hiçbir anlamı yoktur.

⚡ @SpringBootTest vs @ExtendWith(MockitoExtension.class)

@SpringBootTest tüm Spring Context'ini, Hibernate'i ve veritabanı bağlantılarını ayağa kaldırır (15-30 saniye sürer).

Oysa @ExtendWith(MockitoExtension.class) Spring Context'ini hiç başlatmaz; saf Java belleğinde 1 saniyenin altında çalışır!

📐

AAA (Arrange - Act - Assert) / BDD (Given - When - Then) Deseni:
GIVEN (Hazırlık): Test verilerini oluştur, kukla mock nesnelere rol ver (when(...).thenReturn(...)).
WHEN (Eylem): Test edilen servisin metodunu çağır (transferService.transfer(...)).
THEN (Denetim): Sonuçları kontrol et (assertEquals), patlayan hataları yakala (assertThrows) ve repo çağrılarını sorgula (verify).

2. Mockito Mental Modeli ve Temel Yapı Taşları

Birim testte test ettiğimiz sınıf Başrol Oyuncusu'dur. İhtiyaç duyduğu diğer sınıflar (veritabanı repoları, mapper'lar vb.) ise bizim talimatlarımızla hareket eden Figüran Kuklalar'dır.

@Mock

Sahte figüran nesnedir. Veritabanına gitmez. İçi boştur. Ne emredersek onu döner.

@Mock AccountRepository repo;

@InjectMocks

Gerçekten test ettiğimiz başroldür. Mockito, yukarıdaki tüm kuklaları bu servise enjekte eder.

@InjectMocks TransferService service;

when().thenReturn()

Kuklaya rol vermektir: "Sana şu IBAN sorulduğunda şu hesabı ver."

when(repo.find(...)).thenReturn(...)

assertThrows(...)

Bomba İmha Uzmanı: Metodun kontrollü olarak hata fırlatmasını bekler. Hata fırlatılmazsa test başarısız olur.

assertThrows(MyException.class, () -> service.run());

verify(...) & never()

Müfettiş: "Sen bu metodu tam 1 kez çağırdın mı?" veya "Hata çıktığı için veritabanına kaydetme metoduna ASLA gitmedin değil mi?" teftişidir.

verify(repo, never()).save(any());

3. Yazdığımız 7 Test Senaryosunun Derinlemesine Analizi

Projemizde TransferService sınıfımız için sırayla geliştirdiğimiz 7 birim testinin mimari gerekçeleri:

1. Happy Path (Başarılı Para Transferi)

✓ 1.09 saniye

Metot Adı: transfer_whenValidRequest_shouldCompleteSuccessfully()

Ne Yaptık? İki hesap tanımladık (TR111: 500 TL, TR222: 500 TL). 100 TL transfer isteği gönderdik. Kilit sırasına göre repo mock'larını hazırladık.

// THEN: Bakiyeler kuruşu kuruşuna denetlenir
assertEquals(0, new BigDecimal("400.00").compareTo(sender.getBalance()));
assertEquals(0, new BigDecimal("600.00").compareTo(receiver.getBalance()));

// THEN: Veritabanına kayıt işlemi 1 kez tetiklenmeli
verify(transactionRepository, times(1)).save(any(Transaction.class));
verify(transferMapper, times(1)).toResponse(any(Transaction.class));

Kritik Mimari Kazanım: Deadlock önleyici "TR111".compareTo("TR222") < 0 mantığı gereği önce ilk hesabın, sonra ikinci hesabın kilitlendiğini ve bakiyelerin doğru hesaplandığını kanıtladık.

2. Idempotency Kalkanı (Mükerrer İstek Koruması)

✓ Passed

Metot Adı: transfer_whenIdempotencyKeyIsPresent_shouldReturnExistingTransfer()

Ne Yaptık? Ağ koptuğunda veya butona çift basıldığında aynı idempotencyKey geldiğinde servisin veritabanındaki eski işlemi bulmasını sağladık (Optional.of(existingTx)).

// Mükerrer istekte veritabanı kilitleri ve kaydetme ASLA çalışmamalı:
verify(accountRepository, never()).findByAccountNumberWithLock(any());
verify(transactionRepository, never()).save(any());
verify(transferMapper, times(1)).toResponse(existingTx);

Kritik Mimari Kazanım: Sistemin mükerrer para çekmesini engelledik ve gereksiz veritabanı kilit maliyetini sıfıra indirdik.

3. Self-Transfer Kalkanı (Kendine Transfer Engeli)

✓ Passed

Metot Adı: transfer_whenSenderAndReceiverSame_shouldThrowSelfTransferException()

Ne Yaptık? Hem gönderen hem alıcı IBAN'ı aynı ("TR111") verildiğinde servisin derhal durmasını test ettik.

// assertThrows bombayı kucağında yakalar
assertThrows(SelfTransferException.class, () -> transferService.transfer(request, idempotencyKey));

// Metot hemen kesildiği için veritabanına HİÇ dokunulmaz
verify(accountRepository, never()).findByAccountNumberWithLock(any());
verify(transactionRepository, never()).save(any());

Kritik Mimari Kazanım: Bellek içi kontrolün gücü. Servis repo aramasına dahi gitmeden isteği anında reddeder.

4. Yetersiz Bakiye Koruması

✓ Passed

Metot Adı: transfer_whenInsufficientBalance_shouldThrowInsufficientBalanceException()

Ne Yaptık? Gönderen hesabın bakiyesini 50 TL yaptık ama 100 TL transfer edilmesini istedik.

// Bakiye yetersizse hata fırlatılır
assertThrows(InsufficientBalanceException.class, () -> transferService.transfer(request, idempotencyKey));

// DİKKAT: Hesaplar kilitlenir (bakiyeyi öğrenmek için) ama ASLA save yapılmaz!
verify(transactionRepository, never()).save(any());

Kritik Mimari Kazanım: Servisin bakiyeyi kontrol edebilmek için önce hesapları kilitlemek zorunda olduğunu, ancak bakiye yetmeyince işlemi kaydedemeden rollback yaptığını doğruladık.

5. Hesap Bulunamadı & UnnecessaryStubbing Dersi

✓ Passed

Metot Adı: transfer_whenAccountNotFound_shouldThrowAccountNotFoundException()

Ne Yaptık? Gönderen hesap için repoya Optional.empty() dedirttik.

// Sadece 1. hesabı mockladık!
when(accountRepository.findByAccountNumberWithLock(senderIban)).thenReturn(Optional.empty());

assertThrows(AccountNotFoundException.class, () -> transferService.transfer(request, idempotencyKey));
verify(transactionRepository, never()).save(any());

Büyük Tecrübe (Fail-Fast): 2. hesabı (receiverIban) da mocklamaya çalıştığımızda Mockito UnnecessaryStubbingException fırlattı! Çünkü kod 1. hesapta patlayıp derhal metottan çıktığı için 2. hesaba hiç ulaşamadı. Bu da bize gereksiz mock yazmamayı öğretti.

6. İnaktif Hesap Kalkanı

✓ Passed

Metot: transfer_whenAccountIsInactive_shouldThrowAccountInactiveException()

Hesaplardan birini AccountStatus.SUSPENDED, diğerini CLOSED yaptık. Servisin AccountInactiveException fırlattığını ve transferi kestiğini doğruladık.

7. Döviz Uyuşmazlığı Kalkanı

✓ Passed

Metot: transfer_whenCurrencyMismatch_shouldThrowCurrencyMismatchException()

Göndereni USD, alıcıyı EUR yaptık. Çapraz kur motoru devrede olmadığı için sistemin CurrencyMismatchException ile transferi anında engellediğini kanıtladık.
